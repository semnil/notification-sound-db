# 要件定義

[English](requirements.md)

ステータス: 2026-08-09 初期要件合意済み

## 1. 目的

OS および主要アプリケーションに同梱されたイベント音ファイルを、文書化した共通の手順で測定する。
YouTube ライブ配信などのコンテンツと同時にローカル通知が再生される場面を検討するための、説明可能で
再現可能な参照データを公開する。

主な想定は、視聴者端末上での配信音声とローカル通知音の競合とする。通知音が配信の音声ミックスに
入った配信者による利用は副次的用途とする。

## 2. 非目標

- 配信音量の推奨値や下限値を提示しない。
- 測定値に「安全」「危険」のラベルを付けない。
- アプリケーションのランキングを提示しない。
- 音源ファイルの測定値を、実際の再生音圧として提示しない。

OS、アプリケーション、プレイヤー、ミキサー、再生機器の設定により実際の相対レベルが変化する
ことを明記する。将来解釈を追加する場合も測定データとは分離する。

## 3. コンテンツの優先度

背景上の優先度は次の順とする。

1. 人の会話
2. ゲーム音やカラオケ音源などの主要コンテンツ
3. 一時的にマスクされても許容できる付随的な BGM

この優先度は、200 Hz–8 kHz エネルギーなどの記述的指標を選んだ理由を説明するものであり、スコアや
推奨値は生み出さない。

## 4. 初期対象

- macOS のシステムイベント音
- macOS に同梱された Apple アプリケーション
- Slack
- Discord
- Microsoft Teams
- Zoom
- LINE

取得元レジストリ、イベント ID、スキーマ、生成器は拡張可能な状態を保つ。

作業ツリーには各取得元の最新の確認バージョンだけを保持する。更新時は以前のスナップショットを
置き換え、過去状態は Git 履歴に残し、参照されなくなった測定値は現行データセットから削除する。

### 4.1 収録するイベント音

バックグラウンドイベントまたはユーザー操作で再生される短い音を対象とする。メッセージ、着信、
通話状態の変化、エラー、処理完了、UI フィードバックを含む。音楽、動画のサウンドトラック、
読み上げコンテンツなどの主要メディアは除外する。

初期のイベント ID は次の通りとする。

- `message`
- `incoming_call`
- `call_state`
- `error`
- `completion`
- `ui_feedback`
- `system_alert`
- `unknown`

分類は取得元での出現ごとのメタデータであり、測定された性質ではない。用途が不確かなものは推測も
黙った除外もせず、`unknown` のまま保持する。

## 5. 音源の取り扱い

- 正規化、ゲイン変更、リサンプリング、不可逆変換をせず、同梱ファイルを測定する。
- SHA-256、バンドル内の相対パス、OS／アプリ版、取得来歴を保持し、元音源はリポジトリに
  保存しない。
- ローカルにないアプリは公式配布物を一時領域にダウンロードできるが、インストール・実行しない。
  URL と SHA-256 を記録し、測定後は配布物、展開済みアプリ、元音源を削除する。
- 認証、暗号化、アクセス制御、DRM を回避しない。代わりに、取得できない対象を明示的に記録する。

## 6. 測定項目

- Integrated Loudness（LUFS）
- 最大 Momentary Loudness（400 ms、LUFS）
- 最大 Short-term Loudness（3秒、LUFS）
- Loudness Range（LU）
- True Peak（dBTP）と Sample Peak（dBFS）
- 全区間と有音区間の RMS（dBFS）
- 重複なしの短時間 RMS 包絡線（dBFS、最大400点）
- Crest Factor
- 長さ、有音区間の長さ、先頭・末尾の無音
- チャンネル別レベルとチャンネル構成
- 広帯域と 1/3 オクターブ帯のエネルギー
- スペクトル重心、ピーク周波数、200 Hz–8 kHz エネルギー比
- コーデック、サンプルレート、ビット深度、ツール、規格、パラメーター、実行日時

厳密なパラメーターは `config/analysis-profile.json` で版管理し、測定方法文書で説明する。

## 7. データと公開方法

- GitHub に保存し、GitHub Pages で静的レポートを公開する。
- 整形済み JSON を正本とし、ハッシュ単位の測定値と現行の取得元での出現を分離し、JSON Schema で
  検証し、JSON から読みやすい CSV／HTML を生成する。
- リポジトリの正本テキスト、フィールド名、単位識別子、分類 ID は英語とし、利用者向け文書と
  レポートには日本語版を併設する。
- データはローカル CLI で手動更新する。GitHub Actions は検証、生成結果の確認、レポートの構築と
  配備を担当する。定期的な更新検出や測定は初期要件に含めない。

## 8. 根拠と再現性

規格、ツール版、パラメーター、測定日時、ハッシュ、取得来歴を記録する。引用した規格で定義されて
いない記述的指標は、計算式と目的を文書化する。

## 10. 静的サイトの情報設計

次の既存サービスの機能と全体的な情報密度を参考にし、意匠は複製しない。

- <https://ai-compare.semnil.com/ja/>
- <https://koe-zukan.semnil.com/>

中央寄せで情報密度の高い構成、目立つ検索・絞り込み、全データ列の昇順・降順ソート、一覧から詳細への
段階的な導線、件数とスナップショット日時の表示、値・単位・来歴・注意事項の明確な区別、英日切り替え、
レスポンシブでキーボード操作できる動作、JavaScript なしでも有用なリンク、canonical／alternate／OG
メタデータ、JSON／CSV のダウンロードを提供する。音源は保存・再生しない。

英日すべてのcanonicalページを収録し、相互の `hreflang` と `x-default` を持つXMLサイトマップを
ルートに生成して `robots.txt` から参照する。正方形SVG faviconは安定したルートURL
`/favicon.svg` で公開し、全ページから参照する。

全ページのフッターに「問題を報告」リンクを設ける。リンク先は本リポジトリで固定・ロックした恒久
フィードバックIssueとし、このIssueがGitHubアカウントのない利用者をログイン不要の共通フィードバック
フォームへ案内する。

各詳細ページでは正本の RMS 包絡線からレスポンシブな時間推移 SVG を生成する。表示範囲は
0〜−80 dBFSに固定し、有音判定閾値を示し、表示下限未満の値もJSONには保持されると明記する。
LUFSの時系列や波形であるかのように表現しない。

1/3オクターブ測定値は一般的なスペクトラムアナライザと同じ向きで表示し、横軸は左から右へ
高くなる周波数、縦軸はdBFSの帯域エネルギーとする。この表示変更は正本の測定値に影響しない。

PCでは長い結果表を画面高に応じたスクロール領域へ収める。列が横方向にはみ出す場合は、通常の
スクロールバーに加えて、常時操作できるキーボード対応の左右移動ボタンを表示する。ラベル付き
カード表示は狭いモバイル画面だけで使用する。

初回アクセス時は、通常OS設定を反映するブラウザの優先言語順から英語または日本語を選ぶ。
利用者が言語を明示的に切り替えた場合はブラウザのローカルストレージに選択を保存し、以後は
自動判定より優先する。言語変更時は現在のページ、クエリパラメーター、フラグメントを維持する。
