# 測定方法

[English](methodology.md)

## 対象と信号経路

各レコードは、OS またはアプリに同梱された元ファイルの先頭音声ストリームを記述します。
FFmpeg で元のサンプルレートとチャンネル数を保ったインターリーブ形式の 64-bit float PCM に展開します。
解析器は正規化、ゲイン変更、リサンプリング、不可逆な中間変換を行いません。
展開信号は解析の材料としてだけ使用し、保存しません。

機械可読な厳密なパラメーターは [`config/analysis-profile.json`](../config/analysis-profile.json)
にあります。各レコードはこのプロファイルを名前で示すため、互換性のない将来の方式は新しいプロファイル
ID のもとで共存できます。

## Loudness と True Peak

FFmpeg の `ebur128` フィルターを True Peak 測定を有効にして使用し、**ITU-R BS.1770-5 / EBU Mode** に
基づいてラウドネスを測定します。データベースには次を記録します。

- Integrated Loudness（LUFS）
- 400 ms の Momentary Loudness の最大値（LUFS）
- 3秒の Short-term Loudness の最大値（LUFS、音源が3秒以上の場合）
- Loudness Range（LU、音源が3秒以上の場合）
- True Peak（dBTP）

短いイベント音の後でもメーターが確定したフレームを出力するよう、測定フィルター内だけで 3.1 秒の無音を
末尾に追加します。元サンプルと記録する長さは変えません。追加する末尾はデジタル無音であり、最大値や
ピークを増加させることはありません。元音源が 400 ms または3秒の窓より短い場合、レコードに注記を付け
ます。3秒未満では Short-term Loudness と LRA をゼロとして示さず、JSON `null` として保存します。

このプロファイルが参照する規格は [ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I/en)
と [EBU Tech 3341](https://tech.ebu.ch/docs/tech/tech3341.pdf) です。

## Sample Peak、RMS、Crest Factor

`x[n,c]` をフレーム `n`、チャンネル `c` の展開済み float サンプル（デジタルフルスケール = 1）とします。
全区間 RMS は全サンプル・全チャンネルを合成します。

```text
RMS = sqrt(sum(x[n,c]^2) / (frame_count * channel_count))
RMS_dBFS = 20 * log10(RMS)
```

Sample Peak は全チャンネルの展開済みサンプルの絶対値の最大です。Sample Crest Factor は
`sample_peak_dBFS - RMS_dBFS`、True-peak Crest Factor は Sample Peak を True Peak に置き換えた値です。
チャンネル別 RMS と Sample Peak は、チャンネルを合成せずに同じ式で計算します。

## 有音区間

有音は重複しない 10 ms フレームで検出します。フレーム RMS は全チャンネルを合成します。閾値は次の通り
です。

```text
max(-60 dBFS, maximum_frame_RMS_dBFS - 40 dB)
```

最初に閾値以上となるフレームの先頭から、最後の該当フレーム末尾までを有音区間とし、有音区間の
RMS、開始・終了、長さ、先頭・末尾無音を保存します。これは本プロジェクト独自の記述的処理であり、規格上の
Loudness Gate ではありません。

## RMS レベル包絡線

時間推移グラフは、重複しない各フレームに全サンプル・全チャンネルの RMS と同じ式を適用します。
フレーム長は10 ms以上とし、長い音源では系列が400点以下になるよう自動的に広げます。各点の時刻は
フレーム中央です。最後のフレームは残りの元サンプルだけを使い、無音でパディングしません。

正本JSONには各点の時刻（秒）とRMS（dBFS）を保存し、デジタル無音は `null` のままにします。
詳細ページ間で比較しやすいようグラフの表示範囲は0〜−80 dBFSに固定し、それ未満の値は描画時だけ
下端に固定します。データ自体は表示下限で切り捨てません。これはRMS包絡線であり、波形、LUFSの
時系列、元音源を復元できる表現ではありません。

## 周波数特性

記述的な周波数解析のため、チャンネルは算術平均で 1 つにまとめます。Welch 法のパワースペクトル密度
推定には、Hann 窓、最大 4096 サンプルのセグメント、50% オーバーラップ、detrend なし、元のサンプル
レートを使います。対象範囲は 20 Hz から 20 kHz または Nyquist の低い方までです。

広帯域と公称 1/3 オクターブ帯のエネルギー（dBFS）、スペクトル重心、PSD 最大周波数、解析したエネルギー
のうち 200 Hz–8 kHz が占める割合を記録します。最後の値は、人の声を主要なコンテンツとする前提で選んだ
広い周波数重なりの記述値にすぎず、音声明瞭度、可聴性、マスキングのスコアではありません。算術平均では
逆相成分が相殺され得るため、時間領域のチャンネル別レベルも保持しています。

## 来歴、重複排除、測定不能値

SHA-256 で元ファイルを正確に識別します。現行の複数パスに同じバイト列がある場合は、1つの
`data/assets/<sha256>.json` レコードを共有します。取得元レコードには相対パス、分類、版、確認日時、
公式 URL、取得方法と、配布物を一時取得した場合はそのハッシュを記録します。解析の失敗は架空の測定値で
補わず、取得元レコードに残します。シンボリックリンクの先が測定対象のパスの外にあるファイルは読まず、
SHA-256 を `null` とした失敗として残します。アプリの `Contents/Info.plist` の実体がバンドルの外にある
場合も読まず、Info.plist が無い場合と同じに扱います。

JSON `null` は常に測定不能・未定義を意味し、ゼロを意味しません。元音源、配布物、展開済みアプリは公開
しません。

## 解釈の境界

掲載値はデジタル元ファイルの測定値であり、アプリのミキサー出力、配信エンコーダー、ヘッドホン、
スピーカー、聴取位置の測定値ではありません。OS 音量、アプリ別ゲイン、減衰、ミキシング、ダイナミクス
処理、再生機器、環境で実際の関係は変化します。このため配信音量の推奨値・下限、安全判定、製品順位を
導きません。
