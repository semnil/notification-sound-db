# 測定方法

[English](methodology.md)

## 対象と信号経路

各レコードは、OS またはアプリに同梱された元ファイルの先頭音声ストリームを記述します。
FFmpeg で元のサンプルレートとチャンネル数を保った 64-bit float PCM に展開し、正規化、ゲイン変更、
リサンプリング、不可逆な中間変換は行いません。展開信号は測定中だけ使用し保存しません。

厳密なパラメーターは [`config/analysis-profile.json`](../config/analysis-profile.json) にあります。
各レコードはプロファイル ID を持ち、互換性のない将来の方式は別 ID として扱います。

## Loudness と True Peak

FFmpeg の `ebur128` フィルターを True Peak 有効で使用し、**ITU-R BS.1770-5 / EBU Mode** に基づいて
Integrated LUFS、最大 Momentary LUFS（400 ms）、最大 Short-term LUFS（3秒）、LRA（LU）、True Peak
（dBTP）を測定します。

短いイベント音の後までメーターを確定させるため、測定フィルター内だけで 3.1 秒のデジタル無音を
末尾に追加します。元サンプルと記録する長さは変えません。無音は最大値やピークを増加させません。
元音源が 400 ms または3秒より短い場合は注記し、3秒未満では Short-term と LRA を JSON `null` と
します。参照規格は [ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I/en) と
[EBU Tech 3341](https://tech.ebu.ch/docs/tech/tech3341.pdf) です。

## Sample Peak、RMS、Crest Factor

`x[n,c]` をフレーム `n`、チャンネル `c` の float サンプル（デジタルフルスケール = 1）とすると、
全区間 RMS は次の通りです。

```text
RMS = sqrt(sum(x[n,c]^2) / (frame_count * channel_count))
RMS_dBFS = 20 * log10(RMS)
```

Sample Peak は全チャンネルの絶対値最大サンプルです。Sample Crest Factor は
`sample_peak_dBFS - RMS_dBFS`、True-peak Crest Factor は Sample Peak を True Peak に置き換えた値です。
チャンネル別 RMS と Sample Peak も同じ式で計算します。

## 有音区間

全チャンネルをエネルギー合成した重複なし 10 ms フレームの RMS を使います。閾値は次の高い方です。

```text
max(-60 dBFS, maximum_frame_RMS_dBFS - 40 dB)
```

最初に閾値以上となるフレームの先頭から、最後の該当フレーム末尾までを有音区間とし、RMS、開始、
終了、長さ、先頭・末尾無音を保存します。これは本プロジェクト独自の記述的処理であり、規格上の
Loudness Gate ではありません。

## RMS レベル包絡線

時間推移グラフは、重複しない各フレームに全サンプル・全チャンネルの RMS と同じ式を適用します。
フレーム長は10 ms以上とし、長い音源では系列が400点以下になるよう自動的に広げます。各点の時刻は
フレーム中央です。最後のフレームは残りの元サンプルだけを使い、無音でパディングしません。

正本JSONには各点の時刻（秒）とRMS（dBFS）を保存し、デジタル無音は `null` のままにします。
詳細ページ間で比較しやすいようグラフの表示範囲は0〜−80 dBFSに固定し、それ未満の値は描画時だけ
下端に固定します。データ自体は表示下限で切り捨てません。これはRMS包絡線であり、波形、LUFSの
時系列、元音源を復元できる表現ではありません。

## 周波数特性

チャンネルの算術平均信号について、最大 4096 サンプルの Hann 窓、50% オーバーラップ、detrend なし、
元サンプルレートで Welch PSD を計算します。対象範囲は 20 Hz から 20 kHz または Nyquist の低い方です。

広帯域と公称 1/3 オクターブ帯のエネルギー（dBFS）、スペクトル重心、PSD 最大周波数、200 Hz–8 kHz
のエネルギー比を保存します。最後の値は、人声を主な背景コンテンツとするため選んだ広い周波数重なり
の記述値にすぎず、明瞭度、可聴性、マスキングのスコアではありません。算術平均では逆相成分が相殺
され得るため、時間領域ではチャンネル別測定値も保持します。

## 来歴、重複排除、測定不能値

SHA-256 で元ファイルを識別し、同じバイト列が複数パスにある場合は1つの
`data/assets/<sha256>.json` を共有します。取得元レコードには相対パス、分類、版、確認日時、公式 URL、
取得方法、一時取得した配布物のハッシュを記録します。失敗は架空の値で補わず取得元レコードに残します。
JSON `null` は常に未取得・未定義でありゼロではありません。元音源、配布物、展開済みアプリは公開しません。

## 解釈の境界

掲載値はデジタル元ファイルの測定値であり、アプリのミキサー出力、配信エンコーダー、ヘッドホン、
スピーカー、聴取位置の測定値ではありません。OS 音量、アプリ別ゲイン、減衰、ミキシング、ダイナミクス
処理、再生機器、環境で実際の関係は変化します。このため配信音量の推奨値・下限、安全判定、製品順位を
導きません。
